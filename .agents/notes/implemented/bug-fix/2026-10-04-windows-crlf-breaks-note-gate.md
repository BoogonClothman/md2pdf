# Agent Note: Windows 检出打破 Agent Notes 门禁

Status: implemented

## 问题

门禁 `verify:notes` 在 Windows CI 上失败，而同一提交在 Linux 与 macOS 上通过。
失败点是格式校验而非结构校验，症状为连续三条：

```
第 2 行须为空行
第 3 行须符合 implemented 的状态语法：`Status: implemented`
第 4 行须为空行
```

根因是行尾：仓库没有 `.gitattributes`，Windows runner 检出的是 CRLF。门禁读文件后
直接 `split('\n')`，于是每个行尾残留 `\r`——空行成了 `"\r"`，
`Status: implemented` 成了 `"Status: implemented\r"`，而门禁对第 2/3/4 行与规范章节名
做的是**逐字相等**判断，全部落空。

该缺陷自门禁加入起就存在，未暴露的原因是：**仓库此前一份 Agent Note 都没有**，
逐文件格式循环从未在 Windows 上真正执行过任何 Note。首份 Note 入库时它第一次显形——
即"规则要求留痕、但事实一份都没有"这个缺口，本身还掩盖了一个可移植性 bug。

## 决策

两层，主修在门禁，辅修在检出侧。

**门禁归一化行尾。** `scripts/verify-agent-notes.mjs` 新增 `toLF()`，在读入时把
`\r\n` 与孤立的 `\r` 统一为 `\n`，用于两处：`proseLines()`（覆盖章节名与链接检查）
与逐文件格式循环的行数组。判定语义不变——仍然逐字比较，只是比较前先归一化。

**检出侧再堵一层。** 新增 `.gitattributes`（`* text=auto eol=lf`），让任何平台检出
都是 LF，同时消除 CRLF 造成的 diff 噪音。

两个改动配一个 bug-fix Note（本文件），因为"跨平台门禁为何要归一化"属于维护者
会重新审视的决策，而非机械编辑。

## 曾考虑的替代方案

**只加 `.gitattributes`（否决）。** 最省事，但把强制力放在检出侧：贡献者若设置
`core.autocrlf=false` 或全局属性覆盖，门禁会再次失败，而 CI 只会给出三条语义不明的
"须为空行"。逻辑应当与检出方式无关，归一化必须做在门禁里。

**用宽松正则匹配（如 `/^Status: implemented\r?$/`）（否决）。** 等价于允许行尾
多余字符，会同时放过真正的行尾空白错误，逐字校验的严格性被削弱。归一化换行符与
容忍行尾空白是两件事。

**只归一化被严格比较的字段（否决）。** 逐字段加 `\r?` 属于"知道自己在哪一行比较"
的补丁式修法；章节名、`Archived:` 行、链接行同样受影响，漏一处就继续报假故障。

**关闭 Windows job（否决）。** 平台相关的检查（安装包、原生窗口行为）正需要三平台
覆盖；为了绕开门禁 bug 而砍掉平台覆盖，代价远高于修脚本。

## 后果

**收益。** 门禁在三平台行为一致，判定逻辑与检出方式解耦；
`.gitattributes` 让仓库内文本统一为 LF，减少 diff 噪音与未来同类误报；
修复保留了"逐字校验"的严格语义，没有用放宽匹配换取通过。

**代价。** 门禁在比较前多做一次全量归一化，意味着"逐字"实际含义是"归一化后逐字"——
这一点必须由本 Note 与脚本注释共同声明，否则后来者会以为脚本比较的是原始字节。
`.gitattributes` 对已入库文件不重写历史，已有文件的 CRLF 若存在需另行处理（当前无）。

**验证。** 本地以 `git archive` 全量克隆后对 `*.md` / `*.mjs` / `*.json` 注入 CRLF，
复现出与 Windows CI 完全相同的三条报错；修复后同一场景通过。
CI 本身无法构造 CRLF 检出（runner 已带 `.gitattributes` 生效），
故这一条以手工模拟兜底，不设自动回归。
