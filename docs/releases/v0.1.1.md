# md2pdf v0.1.1

今天，我们正式发布 md2pdf v0.1.1。

小版本迭代：编辑区新增**实验性语法高亮**，外加两处修复（分栏拖拽、Windows
安装后的应用名）。核心的「Markdown → PDF 所见即所得」导出管线没有变动。

## 下载

| 平台 | 文件 | 说明 |
|---|---|---|
| **Windows** | `md2pdf-0.1.1-win-x64.exe` | NSIS 安装器（可选安装目录） |
| **Windows 便携版** | `md2pdf-0.1.1-win-x64-portable.zip` | 解压即用，免安装 |
| **macOS (Apple Silicon)** | `md2pdf-0.1.1-mac-arm64.dmg` | 未签名：首次打开需 **右键 → 打开** |
| **macOS (Intel)** | `md2pdf-0.1.1-mac-x64.dmg` | 同上 |
| **Linux** | `md2pdf-0.1.1-linux-x86_64.AppImage` | `chmod +x` 后运行；无 fuse 用 `--appimage-extract-and-run` |
| **Linux (deb)** | `md2pdf-0.1.1-linux-amd64.deb` | `sudo dpkg -i`（缺依赖时 `sudo apt-get install -f`） |

完整性校验见 `SHA256SUMS.txt`。

## 新增

- **实验性：编辑区语法高亮** —— Markdown 源码编辑区现在会给标题、引用、
  列表、链接、强调、行内代码与围栏代码着色（GitHub 风格浅色主题，与预览一致）
  - 实现是把 `textarea` 的文字设为透明，身后叠一层 `<pre>` 显示高亮结果，
    两层逐像素对齐、同步滚动，光标与选区仍是原生 textarea 的行为
  - 围栏代码块内按语言逐行走 highlight.js 真实分词（```js / ```ts …）
  - 标记规则是行级状态机：未配对的 `_`（例如 KaTeX 的 `\int_0`）不会让
    强调样式一路"跑飞"到文档结尾
  - 输入按 50ms 节流重绘；单个文档超过 1MiB 时自动回退为无高亮纯文本
  - **标注为实验性**：配色与开关策略可能在后续版本调整

## 修复

- 分栏拖拽：拖动中间分隔条时，旧代码按位置取 `split.children` 的前两个元素，
  把 `flex` 加到了分隔条自己身上、预览栏反而没被调整，一拖就把布局挤乱；
  现在按元素引用设置，拖动只改变左右两栏宽度
- **Windows**：安装后「设置 → 应用 / 控制面板」显示成 `md2pdf 0.1.0`，
  现在只显示 `md2pdf`（版本仍由系统的「版本」列单独给出）
  - 原因是 electron-builder 的 `nsis.uninstallDisplayName` 默认值
    `${productName} ${version}`，已在 `package.json` 覆盖为 `${productName}`
- 关于对话框的版本号改为读取 `app.getVersion()`，不再写死，
  以后不会再出现"About 页版本落后一个版本"的问题

## 工程

- 发行流水线改为 tag 驱动：推送 `vX.Y.Z` 即自动校验 `docs/releases/<tag>.md`
  与 `package.json` 版本一致后发布 GitHub Release
- Agent Notes 门禁（`npm run verify:notes`）进 CI，三平台执行

## 已知限制

- 高亮为实验性功能，暂无设置开关（始终开启）
- macOS 构建**未签名未公证**（首次启动需右键 → 打开，
  或 `xattr -dr com.apple.quarantine /Applications/md2pdf.app`）
- `.npmrc` 镜像键在 npm 13 前产生警告（已知技术债，见 README）
